## 是什么／怎么做

知识被保存、分类或生成，不等于有人能在需要时找到并据此完成动作。先写清一个目标消费者的问题、触发时机、需要的最小结论和可回指来源；再用真实查询或任务验证它能被召回、读懂并改变下一步。找不到消费者、来源无法核对或不能指导行动的内容保留为材料，不把它计为可用知识。

结构校验、账本健康、召回排名和流程评分只证明产物可解析、可追踪或可找到，不证明信息保真和任务可用。历史样本曾在这些门禁全部通过后仍被用户否定，根因是业务事实覆盖不足、抽象比例过高和人物证据过早泛化。验收还要比较 Source 到卡片的事实覆盖与遗漏，并用未参与规则设计的真实问题检查能否回答；只命中卡片不能计为价值闭环。

多环节链路按真实入口、必经组件、持久化产物和最终消费者逐层验收。单个 loop 返回成功、若干 Agent 执行完或一条决策记录完成回填，只能证明对应阶段；还要检查未执行的入口、未自动生成的报告和遗留中间态。历史样本中三个 loop 返回正常时，存储仍有 pending 条目，报告触发和周期调度也未接通，因此不能据此宣称自治链路完成。

不同知识类型不能共用一套摘要模板。架构知识保留系统节点、调用边、边界和当前／规划差异；业务知识保留对象、流程、服务、入口、字段、状态和代码锚点；只有 Playbook 才强制步骤与检查项。先从原文还原事实，再标出综合、推断、冲突和未知，最后生成面向任务的消费视图。没有耐久结论时明确不产卡是正确结果；确定性校验负责拦坏格式、缺引用和合同缺失，不能用字数或字段齐全代替语义保真。关键事实覆盖和结论证据仍需独立核对。

强依赖代码、文档或配置现状的事实，不靠人工复制长期维持。由来源适配器在源变更后重新生成草稿和差异，人工只裁决冲突、准入和高风险语义；无法回读当前来源时保留未知或退休旧结论。自动更新只降低维护成本，不自动保证知识准确，生成结果仍要经过来源回指与消费者验证。

消费留痕要把查询、进入上下文、实际采用和结果反馈分开。召回但未影响产物记为 `unused`，不能冒充使用；`helpful`、`partial` 或 `incorrect` 只有在知识确实影响了检查、决策、代码或文档，并能回指最终产物时才成立。零结果和低相关召回也是检索质量信号，不用弱相关卡凑满上下文。

评估知识库效果时比较真实任务结果，而不是卡片数、流程终态或结构健康。冻结任务与基线后，观察事实错误、关键遗漏、首次通过、人工修改量、修复轮次和成本；真实使用样本不足时结论写 `inconclusive`。反馈的用途是驱动冻结、修订、降权或验证升级，不是为流程补一个成功状态。

## 什么时候用

整理笔记、建设知识库、设计检索、复盘经验，或判断一批内容是否值得继续维护时使用。

## 什么时候别信

消费者问题会变化，过去可用的卡片可能已经过期。高风险决策仍要回读当前权威来源；召回一次不代表长期覆盖率或业务价值已经成立。旧系统的 loop、Agent、状态名和完成数字只用于说明验收分层，不证明当前 Runtime 仍采用同一结构。
