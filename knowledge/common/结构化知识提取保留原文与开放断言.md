## 是什么／怎么做

原文是证据真源，结构化字段、摘要、断言和向量都是派生索引，不能覆盖或替代原文。提取结果要保留精确来源；召回命中后允许回到原文或对应片段。全文或分块索引可以兜底检索遗漏，但不能替代提取质量，因为评分、冲突判断和下游生成仍会直接消费结构化字段。

文档正文、评论、图片和 Drawio 是不同证据载体。采集时分别保留原始正文、评论内容和图像解析结果，在正文位置只放概括与精确引用；不要把 OCR、图像理解或评论解释改写进原文。这样既能让消费者连续阅读，也能在解析错误时只重做派生结果。

图像处理还要逐张区分传输成功、任务终态、模型实际看到像素、结构可解析和语义与上下文一致。生成了 N 份 JSON 不等于 N 张图识别正确；历史批处理中曾同时出现图片未正确内联、模型返回“空白”、结构解析失败和与文档主题无关的幻觉，但汇总仍先写成“30/30 成功”。保留原图、每张图的原始返回、执行路径和 fallback 标记；云端结果不可信时只替换该张派生解析，并由能直接查看原图的消费者复核，不能让本地补读后的总成功数冒充云端识别率。

事实断言用于冲突比对、相关性判断和语义检查，不是任意摘要。数量规则只能规定最低覆盖，不能给所有文档设统一上限；操作手册可能只有少量稳定事实，高密复盘可能有大量数字、条件和结论，应把所有值得比较和核验的事实提出来。固定“最多五条”会直接剪掉高密文档的有效证据。

同次提取要报告哪些章节未被结构化覆盖及原因，区分原文只有图片／外链、schema 没有承载位和实际漏提。重要缺口进入质量标记并回源补充，普通附录或结构限制不伪装成提取成功。提取 Prompt、schema 或断言合同改变后，要重跑受影响语料并比较结果；单篇样本通过不能证明存量已经迁移。

完整度要同时检查两个方向：来源原子事实有多少进入事实包和最终视图，用来发现遗漏；输出主张有多少能反查到来源，用来发现失真和硬编。按章节、表格、图片、评论线程和消息回复链拆分来源单元，每个单元必须明确为已抽取、仅上下文、阻断或其他可解释终态，不能只写“已处理”。报告还要分开“已处置、实际抽取、进入最终视图、显式阻断”，避免用 100% 处置率掩盖内容损耗。

事实召回率和任务问题覆盖比压缩比更重要。加权总分不能让一条否定规则、金额口径或状态跃迁被大量背景事实抵消；关键事实必须逐条处置，无法保留时写成 Gap 或 conflict。长文先分段保真抽取，再按实体、流程、决策和时间轴合并；最终视图不强制固定长度，也不把逐行复述误当成完整知识。

最终正文应从已经核验的类型化视图确定生成，不能让发布阶段重新自由摘要。来源单元的证据哈希按原始字节计算，展示字段可以规范化空白；若先 `trim` 再校验，会让格式变化被误当成证据一致或让同一来源自校验失败。

## 什么时候用

设计长文提取、知识准入、冲突检测、召回索引，或修改提取 Prompt 和断言数量约束时使用。

## 什么时候别信

来源中的 JSON 字段、TF-IDF、分数和文档数量是 2026-07 的历史实现。本卡不要求恢复旧提取链，也不指定当前索引技术；当前消费者和原文回溯能力必须按现行系统核对。
