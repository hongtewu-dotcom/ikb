# 知识查询、使用与效果留痕契约

## 要解决的问题

`搜到一条知识`不等于`这条知识真正帮助了任务`。如果只记 Context Pack 和引用次数，后续只能知道知识曾经出现过，无法回答下面这些问题：

- Agent 搜过什么，哪些查询没有结果；
- 哪些知识只是被召回，哪些真正进入了交付物；
- 知识帮助了哪个判断、段落、检查或行动；
- 使用后是有效、部分有效、错误，还是最终没有采用；
- 哪些低相关召回、知识缺口或错误规则需要进入维护循环。

因此，IKB 把一次知识消费拆成四个不可混淆的事实。

## 四层事实

| 层次 | 事件 | 说明 | 必要绑定 |
| --- | --- | --- | --- |
| 查询 | `knowledge.query_executed` | Agent 确实执行了一次搜索或 Context 查询，零结果也记录 | 查询文本、scope、过滤条件、结果 ID 与分数；Context 查询再绑定 Task/Run |
| 引用 | `knowledge.referenced` | 某条知识进入了本次 Run 的 Context Pack | Knowledge、Task、Run、Context Artifact、查询 ID |
| 使用 | `knowledge.used` | 某条知识确实影响了交付物 | Knowledge、Run、引用事件、同 Run 且 hash 有效的 Artifact、具体用途和人话说明 |
| 效果 | `knowledge.feedback_recorded` | 对本次召回或使用作出最终分类 | `helpful / partial / incorrect / unused`、原因码、同 Run 证据 Artifact；审阅后拒绝用 `unused + reviewFinding=incorrect` 表示 |

## 硬约束

1. `ikb search` 和 `ikb context` 每执行一次都写查询事件；没有结果也不能省略。
2. Context 查询只表示召回。Agent 真正采用知识时，必须执行 `ikb knowledge use`，并说明它影响了哪个决定、段落、检查或行动。
3. `knowledge use` 只能引用同一 Run 已召回的 Knowledge，且必须绑定同一 Run 中内容 hash 仍然有效的 Artifact。
4. 四种反馈都必须绑定同一 Run、内容 hash 仍有效的 Artifact。`helpful / partial / incorrect` 必须已有实际使用记录；`unused` 必须没有实际使用记录。
5. 同一 Knowledge 在同一 Run 只有一个最终反馈。相同命令可幂等重放，不同结论必须显式修订，不能悄悄覆盖。
6. 采用本契约的新 Run，只要存在未分类的 Knowledge 引用，就不能以 `succeeded` 收口；失败和取消仍允许结束，并在报表中保留缺口。
7. 历史 Run 没有新查询契约事件时不追溯阻断，避免破坏既有账本。

## 审阅后发现错误但未采用

普通 `incorrect` 只表示 Knowledge 已经通过 `knowledge use` 影响了交付物，之后被一手证据判错。审阅时发现问题、但在进入交付物前就拒绝的卡片，不能补写 `knowledge use`，也不能把它伪装成普通 `incorrect`；它仍是 `unused`，并在最终反馈中附带 `reviewFinding=incorrect`。

这条反馈必须已有同一 Run 的引用、没有该 Knowledge 的 `knowledge use`、带非空 `reason-code` 和 `note`，并引用同一 Run 且 hash 有效的证据 Artifact。仓库根目录下可直接运行：

```bash
./bin/ikb knowledge feedback <knowledge-id> --run <run-id> --outcome unused --review-finding incorrect --reason-code source_conflicts_with_current_state --note "审阅发现来源与当前一手事实冲突，未写入交付物" --evidence <artifact-id> --json
```

它和其他最终反馈一样会闭合父卡引用，但不会生成使用事件。`knowledge usage-status --run <run-id> --json` 会单列 `reviewedIncorrectUnadoptedKnowledgeIds` 与 `reviewedIncorrectUnadoptedKnowledgeCount`；旧 payload 没有 `reviewFinding` 时返回空列表和零，不改变历史 Run 的收口语义。

## 本地可分析指标

日报和周报至少展示：查询总数、搜索与 Context 分布、零结果数与比例、引用数、实际使用数、用途分布、四类反馈、未分类引用数、存在缺口的 Run 数，以及引用到实际使用的转化率。审阅后拒绝另在 `knowledgeUsage.feedbackReviewFindings.incorrect` 聚合，不能增加普通 `knowledgeUsage.feedback.incorrect`。

这些指标只说明检索和使用闭环是否发生，不直接证明知识正确。知识正确性仍以 Source、Artifact、验证结果和真实任务反馈为准。
