# IKB 模块边界与保障

更新：2026-07-22

## 结论

IKB 的概念架构分成 Source、Candidate、Experience/Person、Knowledge、Execution、Control、Eval、Report 八个边界。本轮已经修复此前两个主要的物理结构问题：

1. `src/cli.ts` 从 1,800 多行缩为纯路由入口；命令按 Control、Source、Candidate、People、Knowledge、Harness Eval、Analysis、Observation 和 System 分开。
2. `src/knowledge.ts` 从实现大杂烩缩为稳定门面；内部按 contracts、catalog、codec、storage、records、quality、repository、views 和 lifecycle 单向依赖。
3. 维护计划成为纯模块；历史 Run 修复属于 Outer Loop，不再混入每日知识维护链。

每日维护仍会对**本次维护 Run**做真实质量评估，但不会顺手修复其他历史 Run。

结构原则是“高内聚、低耦合”：模块围绕一个稳定职责组织；跨模块只走显式 API；状态只有一个写入所有者；子模块不反向依赖公开门面；CLI、报表和评估不得绕过领域 API 修改状态。

## 目标拆分

```text
入口层（CLI / Skill / Report）
  ├─ Source Plane       原始证据、增量、hash、完整性
  ├─ Candidate Plane    外部入口发现、排队、限频、解析状态
  ├─ Analysis Plane     Session Triage、Experience、Person dossier、推理
  ├─ Knowledge Plane    admit / skip、Vault、关系、生命周期、lint
  ├─ Execution Plane    Task、Run、Context、Checkpoint、交接
  ├─ Control Plane      Ledger、Artifact、Approval、Gate、状态投影
  ├─ Eval Plane         Suite、Adapter、真实 Run 评估、回归比较
  └─ Observation Plane  日报、周报、HTML，只读派生视图
```

## 真相源与允许依赖

| 边界 | 真相源 | 允许谁写 | 其他模块如何使用 |
|---|---|---|---|
| Source | `ikb-data/.system/sources` + source 事件 | Intake/connector | 通过 Source API 读，不直接拼路径 |
| Candidate | `governance/*/candidates` + candidate 事件 | Candidate service | 只通过 Candidate API 推进状态 |
| Knowledge | Vault Markdown + knowledge 事件 | Curator/Verifier/用户确认 | 通过 Knowledge API 检索和建 Context |
| Experience/Person | governance 下的可重建投影 | Triage/Person builder | 只能引用 Source，不能冒充 Knowledge |
| Task/Run/Approval/Artifact | `ledger/events.jsonl` | Control API | 投影只能读 Ledger |
| Eval | Eval Artifact + evaluation 事件 | Eval Coordinator | 不反写业务真相，只提供质量证据 |
| Report | `reports/` | Observation | 只读，不允许反向改状态 |

允许的依赖方向：

```text
入口 → Application service → Domain/contract → Store/adapter
Eval → Control read model
Observation → Control/Eval read model
```

禁止 CLI、Report 或 Eval 绕过 API 直接修改其他 Plane；禁止 Knowledge 反向修改 Source；禁止日常维护隐式调用历史 Run repair。

## 每个边界的保障

### Source / Candidate

- 单元测试覆盖规范化、逻辑去重、raw/records hash、增量游标、限频和 `dry-run`。
- `doctor` 检查路径、hash、来源元数据和事件链。
- 权限/密级/网络失败进入 `blocked`；重复输入是 `skipped`，不得重复写 Source。
- 外部来源只读；发送、评论、发布不属于该边界。

### Analysis / Person

- Analysis 只产出 findings、evidence refs、unknowns、conflicts、admit/skip 建议，不直接写 verified Knowledge。
- 人物 dossier 从不可变 Source 重建；人物 Knowledge 还需要身份、独立 Episode、时间有效性和可行动性门禁。
- 回归测试覆盖身份误匹配、上下文共现不计 direct evidence、重复重建幂等。

### Knowledge

- 每条 admit 必须有 `source_refs`、适用范围、边界、使用契约、验证计划和生命周期字段。
- `skip` 也落 rejected Candidate 和理由；知识数量不是质量指标。
- `lint` 检查字段、引用、关系和状态；`verified` 需要真实任务验证或人工确认。

### Execution / Control

- Task 表达业务目标，Run 表达一次尝试，步骤不污染 Task 状态。
- 交接通过 `handoff` 事件和 Artifact 引用；失败必须有原因和恢复出口。
- Approval 绑定目标和载荷 hash；没有 Approval 的 L3/L4 副作用不能执行。
- Ledger hash chain、`doctor` 和 Run Quality 是交付门禁。

### Eval / Observation

- Eval 读取真实 Run 的事件、Plan、Artifact 和 Approval；`terminal=succeeded` 不等于质量通过。
- L1 是硬门禁，L2/L3 只报告和比较；Eval 不反写 Source/Knowledge。
- HTML、日报、周报是 Ledger 的派生视图；报表错误不能改变业务状态。

## 当前物理模块

```text
src/cli.ts                         只解析、装配、路由
src/commands/
  shared.ts                        参数契约
  control.ts                       Task / Run / Approval / Artifact
  catalog.ts                       Agent / Gate / Loop 目录
  harness-eval.ts                  Harness 评估命令
  analysis.ts                      Experience / Reasoning
  observation.ts                   只读观察命令
  source-intake.ts                 Source 接入与上下文
  source-shared.ts                 Source/Candidate 共享限频与事件契约
  candidate.ts                     Candidate 状态推进
  people.ts                        人物 dossier 投影
  knowledge.ts                     Knowledge 命令编排
  system.ts                        init / doctor / backup / ledger / report
src/knowledge.ts                   对外兼容门面
src/knowledge/
  contracts.ts → catalog/codec/storage → records/quality → repository/views/lifecycle
```

当前结构门禁会检查：CLI 不直接依赖领域实现、Knowledge 子模块不反向导入门面、Source/Candidate/People 命令不重新混回同一文件、人物投影不依赖 Knowledge 服务、每日维护不隐式修复历史 Run。

下一阶段若继续拆 Application Service，触发条件不是“文件看着大”，而是同一编排在 CLI、维护任务或 Skill 中出现第二次。届时把重复流程下沉为单一服务，命令层只做输入适配；在出现重复前不预建空抽象。

## 当前验收命令

```bash
pnpm check
./bin/ikb doctor --json
./bin/ikb ledger verify --json
./bin/ikb run show <run-id> --json
./bin/ikb observe daily --json
```

任一命令失败，结果只能交付为 `blocked`，不能用“脚本跑完”替代质量通过。
